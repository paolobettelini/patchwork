# Example: network messages

The network example shows how to create a moddable mechanic without hardcoding
it in the framework.

Goal:

- each mod can declare message payloads;
- the final modpack produces two global enums;
- mods can build, serialize, deserialize, and dispatch those enums;
- the wire format uses CBOR;
- a test can print JSON for debugging.

## Crates involved

```text
network-vanilla-types
  contains payload structs, for example ServerMessage1

network-vanilla-mod
  declares in metadata which payloads go into the final enums

network-codegen-utils
  reads network metadata and generates network-messages

network-messages
  generated crate with ClientBoundMessage and ServerBoundMessage

network-mod-client / network-mod-server
  declare codegen and depend on the generated crate

main-client-mod
  uses the final enums
```

## Declaring messages

A mod declares its messages in `Cargo.toml`:

```toml
[package.metadata.network.messages]
clientbound = [
    "network_vanilla_types::ServerMessage1",
]
serverbound = [
    "network_vanilla_types::ClientMessage1",
]
```

The payloads live in `network-vanilla-types`, not directly in
`network-vanilla-mod`. This separation avoids cycles.

## Declaring codegen

The network mod declares that the modpack must generate `network-messages`:

```toml
[[package.metadata.mod.codegen]]
crate = "network-messages"
version = "0.1.0"
dev_crate = "network-messages"

[package.metadata.mod.codegen.generator]
crate = "network-codegen-utils"
command = "generate"
```

Patchwork runs the generator. The generator visits the mods in the composed
project and searches for `package.metadata.network.messages`.

## Generated output

The result is:

```rust
#[derive(Debug, Clone, serde::Serialize, serde::Deserialize)]
pub enum ClientBoundMessage {
    ServerMessage1(network_vanilla_types::ServerMessage1),
}

#[derive(Debug, Clone, serde::Serialize, serde::Deserialize)]
pub enum ServerBoundMessage {
    ClientMessage1(network_vanilla_types::ClientMessage1),
}
```

The generated crate also exposes CBOR helpers:

```rust
let bytes = message.encode_cbor()?;
let message = ClientBoundMessage::decode_cbor(&bytes)?;
```

## Use from a mod

A mod can build the final enum like normal Rust code:

```rust
use network_messages::{ClientBoundMessage, ServerBoundMessage};
use network_vanilla_types::{ClientMessage1, ServerMessage1};

let clientbound = ClientBoundMessage::ServerMessage1(ServerMessage1 {
    name: "vanilla server message".to_string(),
});

let serverbound = ServerBoundMessage::ClientMessage1(ClientMessage1 {
    name: "vanilla client message".to_string(),
});
```

For debugging, it can serialize to JSON:

```rust
let json = serde_json::to_string_pretty(&clientbound)?;
println!("{json}");
```

JSON is only a smoke test. The intended wire format is CBOR.

## Moddable dispatch

Dispatch should not live in the framework. It can be another mod or another
crate generated by the same network domain.

For example, in the future a generator could produce:

```rust
pub fn dispatch_clientbound(world: &mut bevy_ecs::world::World, message: ClientBoundMessage) {
    match message {
        ClientBoundMessage::ServerMessage1(payload) => {
            world.send_event(payload);
        }
    }
}
```

This would also be domain codegen declared by a network mod. Patchwork would
still only know that it must run a generator.
